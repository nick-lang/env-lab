# env-lab plan — Barrow to Tower

*Rewritten 2026-09-02 after E01, E03 and the first critic. Supersedes the earlier ladder.*
*Amended the same day: the critic (E04) is shelved at the user's call. The user judges every gate directly.
Critiques are logged in `critic/CRITIQUES.md`; what a working critic might be is in `critic/HYPOTHESES.md`.*

## North star

A world description in, an editable streamed Unreal world out. Every asset generated by us.
Quality judged by the user, not by the model that made the thing.
The tower is the target held in mind: "a wizard tower with 50 floors that looks incredible
outside, no floor a variant of the last; later, every floor gates the next; later, highlight
anything and say it looks out of place and it gets fixed." Proving grounds in order:
the **Barrow** (now), a **tower floor**, a **five-floor tower**, a **4 km² region**, a
**sky-fortress village** in the same world's style, the **50-floor tower**.

## What we already know (from E01, E03, critic v1)

- Beauty ≈ asset quality × density × lighting. The model directs; factories produce. Never let it model.
- Concept → image-to-3D → cleanup gives real hero props in minutes (TRELLIS.2). Thin geometry fails.
- Rules-based density works and is cheap. Terrain from heightmaps works.
- A whole-frame pairwise critic on uncontrolled stills only recovers "which experiment made it".
  Judge **elements**, vary **one factor** at a time, ask **what decided it**.
- The user's read: "incredible" may be the easy part; matching a world's feel while changing the
  milieu is what image models are good at. Agreed, with one caveat: *coherence* is the easy part,
  *quality* is not, and the user is the one who tells the two apart.

## Principles

1. Model directs, factories produce, the user judges and canonizes.
2. Everything placed is addressable: object → rule → intent. Fixes happen at the rule, not the mesh.
3. One axis per experiment. Every experiment has a pass gate and a kill criterion.
4. Assets are ours: generated, procedural, or generated-textured procedural. No packs.
5. Style and quality are separate judgments. Quality rubric is universal; style is a board per region.

## Experiments

### E05 — World file rebuilds the Barrow  (L1)  — **PASSED 2026-09-02**
- **Change:** `world.json` describing the Barrow (terrain params, biome rules, dolmen site, path, shots); compiler regenerates Barrow_E1 from it. IDs on every placed object.
- **Pass:** two runs from the same seed produce identical placements; ten random objects in a still resolve to (id → rule → intent) correctly.
- **Kill:** if determinism or addressability cannot be had in Unreal's PCG/HISM path, the compiler owns placement itself (Python) and treats the engine as a renderer.

### E06 — Vegetation we made  (L2)  — **PASSED 2026-09-02** (user: "It already looks so much better")
- **Change:** trunk/branch generator + leaf and grass cards with Flux-generated alpha textures; three species.
- **Pass:** the user prefers them to the procedural kit side by side; reads at 5 m, 50 m, 300 m.
- **Kill:** if cards read badly at distance, add billboards/imposters; if the user still rejects, vegetation gets its own project (SpeedTree-class generator).

### E07 — Materials we made  (L2)  — **PASSED 2026-09-02** (user: "enough to pass for now")
- **Change:** tileable material generator (Flux + seam pass → base colour, roughness, normal) for ground, stone, plaster, wood; replaces the inherited ground material.
- **Pass:** seamless at 4 tiles; the user prefers them to the flat materials; the brick-red ground problem is gone.
- **Kill:** if seams cannot be fixed at 2k, fall back to triplanar procedural blends with generated detail textures.

### E08 — Modular kit with sockets  (L2 + L3)  — **built 2026-09-02, validator clean, awaiting the user's judgment**
- **Change:** a 12-piece stone kit (floor, wall, corner, door, window, stair, landing, pillar, trim ×2, ceiling, cap) generated against a grid spec; socket labels per face; snapping validator; a WFC solver that fills a 20×20×3 room.
- **Pass:** automated check: zero gaps, zero clipping, every socket matched; the room reads as one material language.
- **Kill:** if image-to-3D cannot hold a grid spec, kit pieces become procedural shells with generated materials (E07), and image-to-3D supplies only the ornaments.

### E08b — Build like the gate  (L2)  — **built 2026-09-03, awaiting the user's judgment**
- **Change:** the kit keeps envelopes and sockets; visible surfaces become instanced sculpted blocks from the asset
  factory (block library, coursed masonry assembler, slab floors, stacked pillars), mortar cores behind, weathering
  v1 from baked AO + world position, Nanite, daylight rig. Measurement pack on every still.
- **Pass:** you say it looks good, or at least as good as the gate; repeat score on the hall shots drops from ~0.6
  to Barrow levels (≤0.25); detail energy present in all four octaves.
- **Kill:** if instanced sculpted blocks still read as "pattern", the assembler needs sculpt-level variation per
  block (unique blocks per wall, not a library), which means far more generation time per building.

### E09 — One tower floor with intent  (L3)
- **Change:** mission graph (rooms, connections, one lock, one key) → room layout → pinned door/path cells → WFC fill → dressing rules → look pass.
- **Pass:** path exists from stair-up to stair-down through the lock; the user prefers it to an unconstrained WFC fill; the user can describe the floor in one sentence after walking it.
- **Kill:** if WFC contradictions dominate, switch to room-template stamping with WFC only for corridors.

### E10 — Five floors, none a variant  (L1 + L3)
- **Change:** five archetypes authored as rules + palettes + asset draws from a variance budget.
- **Pass:** the user, shown floors blind, calls them distinct 4 of 5 times; no asset appears on more than two floors unless flagged "signature".
- **Kill:** if distinctness needs hand authoring per floor, the variance budget moves from assets to layout grammar and lighting first.

### E11 — The edit loop  (L5)
- **Change:** ID render per still; "this looks out of place" on a highlighted region → object ids → rule → regenerate the affected region only.
- **Pass:** 8 of 10 user-flagged items fixed in one round without breaking neighbours; nothing outside the region changes.
- **Kill:** if regeneration cascades, region boundaries become part of the world model (explicit cells).

### E12 — Scale  (L6)
- **Change:** one 4 km² region from `world.json`, World Partition, HLOD, millions of instances.
- **Pass:** editor fly-through holds 60 fps; generation under a night; 50 random stills, the user finds nothing below the Barrow's floor.
- **Kill:** if generation time explodes, the compiler gains a coarse-to-fine budget (macro first, detail on demand).

### E13 — Style transfer  (L7)
- **Change:** a region board from our own stills; "an interconnected flying pirate-ship sky-fortress village" generated against it.
- **Pass:** blind "same world?" pairs ≥80% yes from the user; the user rates quality not below the Barrow.
- **Kill:** if style holds but quality drops, style conditioning is fine and the generators are the gap — go back to L2.

### E14 — The 50-floor tower
- Everything above, run end to end; then "every floor gates the next"; then edit passes.
